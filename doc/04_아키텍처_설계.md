## 4. 핵심 컴포넌트

### 4.1 IStreamingProvider (서비스별 동작 추상화)

서비스마다 다른 동작(로그인 감지, 자동 입력, 팝업 처리)을 캡슐화합니다. 기본 서비스는 전용 Provider를 두고, 사용자 정의 서비스는 `GenericProvider`를 씁니다.

```csharp
public interface IStreamingProvider
{
    string Code { get; }                       // "netflix", "tving", ... "generic"
    bool CanHandle(StreamingService service);

    // 현재 URL이 로그인 페이지인지 판단 (DB의 LoginUrlPattern이 있으면 우선)
    bool IsLoginPage(StreamingService service, Uri uri);

    // 로그인 폼 셀렉터 (DB의 LoginFormSpecJson이 있으면 우선)
    LoginFormSpec? GetLoginFormSpec(StreamingService service);

    // 새 창 요청 처리 정책: InApp / OAuthDialog / ExternalBrowser
    // (ExternalBrowser는 외부 링크용이며, 재생을 외부로 넘기는 용도가 아님. D-07)
    NewWindowPolicy ResolveNewWindow(StreamingService service, Uri target);

    // 앱 안에서 탐색을 허용할 호스트 (DB의 AllowedHosts가 비어 있으면 Provider 기본값)
    IReadOnlyList<string> GetAllowedHosts(StreamingService service);

    // 로그아웃 상태를 감지했을 때 이동할 로그인 페이지 (DB의 LoginUrl이 우선, 없으면 null)
    string? GetLoginUrl(StreamingService service);

    // 서비스의 기본 로그인 방식(LoginProviders 상수). 대부분 native지만 치지직은 naver, YouTube는 google처럼
    // 서비스 자체 로그인이 곧 상위 계정 로그인인 경우가 있다. 이 값과 같은 LoginProvider는 자체 ID로 취급한다.
    string PrimaryLoginProvider { get; }
}
```

구현(Phase 1): `StreamingProviderBase`가 공통 로직(DB 값 우선, OAuth 호스트 목록, 호스트 패턴 매칭)을 갖고, 서비스별 클래스는 코드·기본 허용 호스트·로그인 URL 정규식만 정의합니다. `IStreamingProviderResolver`가 `ProviderCode`로 Provider를 찾고 없으면 `GenericProvider`로 떨어집니다. 서비스 목록은 `IServiceCatalog`로 추상화하며, SQLite 저장소 `ServiceRepository`가 구현합니다(Phase 2 완료).

> 결정: 허용 호스트 밖 탐색(`NavigationStarting`)은 막지 않고 로그만 남깁니다. PoC에서 Google 로그인이 accounts.google.co.kr 같은 예상 밖 호스트를 거치는 것을 확인했고, 차단은 예정에 없습니다. `AllowedHosts`는 새 창 요청(`NewWindowRequested`)에서 앱 안·OAuth 대화상자·기본 브라우저를 가르는 데만 씁니다.

### 4.2 ServiceHostControl (WebView2 래퍼)

- 서비스 1개(·계정 1개)당 인스턴스 1개
- 수명: 처음 선택할 때 생성(Lazy) → 비활성일 때 Suspend → 다시 선택하면 Resume
- 구독하는 `CoreWebView2` 이벤트: `NavigationStarting`, `NavigationCompleted`, `SourceChanged`, `DOMContentLoaded`, `DocumentTitleChanged`, `ContainsFullScreenElementChanged`, `NewWindowRequested`, `ProcessFailed`, `PermissionRequested`, `LaunchingExternalUriScheme`, `DownloadStarting`, `WebResourceResponseReceived`. 웹 메시지(`WebMessageReceived`)는 쓰지 않으며 `IsWebMessageEnabled`는 항상 끕니다(스크립트 결과는 `ExecuteScriptAsync`의 반환값으로 받음).
- 주요 처리:
  - `NavigationStarting`: 허용 호스트 밖이면 로그만 남김(차단하지 않음)
  - `NavigationCompleted` / `SourceChanged`(SPA 라우팅): 로그인 페이지면 `LoginPageDetected` 이벤트를 올림 → `LoginAssistService`가 자동 입력
  - `DOMContentLoaded` 또는 URL 1.5초 안정: `PageSettled` 이벤트(로그아웃 상태 판정용)
  - `ContainsFullScreenElementChanged`: `FullScreenElementChanged`를 올리고 `ServiceHostManager` → `MainViewModel.OnFullScreenElementChanged`가 `IWindowService.EnterFullScreen(FullScreenKind.Video)/ExitFullScreen()` 호출
  - `NewWindowRequested`: Provider 정책에 따라 앱 안 / OAuth 대화상자(`OAuthPopupWindow`, 같은 프로필·같은 보안 설정) / 기본 브라우저(http(s)만)
  - `ProcessFailed`: 다시 생성하고 마지막 URL 복원
  - `PermissionRequested`: 자동 재생만 허용. `LaunchingExternalUriScheme`·`DownloadStarting`: 취소

### 4.2.1 ServiceHostManager (App 계층)

- `IServiceHostManager`가 서비스별 `ServiceHostControl`을 만들고(최초 선택 시) 전환합니다. MainWindow가 WebView를 올릴 패널을 `Attach`로 넘깁니다.
- **새 호스트는 보이는 상태로 만든 뒤 초기화**합니다. 숨긴 채 로드하면 페이지 로드가 약 40초 걸립니다(R-20, PoC 실측). 이전 호스트는 그다음에 숨깁니다.
- 전환 시 이전 서비스의 `<video>`를 일시정지합니다(`PauseOnSwitch`, FR-PLY-04).
- 호스트 이벤트(영상 전체화면, URL·제목 변경, 실패)는 활성 호스트의 것만 MainViewModel로 전달합니다.

### 4.3 WebView2EnvironmentProvider

- 앱 전체에서 `CoreWebView2Environment`를 싱글톤으로 하나만 만들고 공유
- 프로필 이름 규칙(D-11): 서비스의 첫 계정은 `svc_{code}`(서비스 프로필과 같아 현재 세션을 그대로 씀), 이후 계정은 `svc_{code}_{GUID N형식}`(최대 40자). 예: `svc_netflix`, `svc_netflix_3f2a...`
- 브라우저 인자: 기본값을 유지하고, 필요하면 서비스별 User-Agent만 조정

### 4.4 WindowService (전체화면)

```
EnterFullScreen(FullScreenKind kind):
  1. 현재 WindowState, WindowStyle, Bounds 저장
  2. WindowStyle = None, ResizeMode = NoResize
  3. 창이 속한 모니터의 전체 영역으로 Bounds 설정 (작업 표시줄 포함)
  4. Topmost = true
  5. FullScreenChanged 이벤트 → MainViewModel.UpdateChromeVisibility가 타이틀바·사이드바·배너 숨김 (IsChromeVisible = false)
ExitFullScreen():
  저장한 상태 복원 → FullScreenChanged
```

WindowService는 창 모양만 바꾸고 셸 UI 숨김은 하지 않습니다. 미니 플레이어(`EnterMini/ExitMini`, `MiniChanged`)도 같은 구조입니다.

- 두 가지 진입 경로를 하나로 합쳐서 처리합니다:
  - **영상 전체화면**: 웹 플레이어의 전체화면 버튼 → `ContainsFullScreenElementChanged`
  - **앱 전체화면**: F11 → 셸 UI만 숨기고 웹페이지는 그대로
- Esc를 누르면 영상 전체화면이면 JS `document.exitFullscreen()`, 앱 전체화면이면 창 상태를 복원

### 5.3 로그인 보조

```
NavigationCompleted (또는 SPA 라우팅 감지: SourceChanged → 0.9초 뒤 같은 URL이면 재확인)
 → [만료 감지]
   ├ Provider.IsLoginPage(uri)               → 로그인 페이지 (LoginPageDetected)
   └ PageSettled(DOMContentLoaded 또는 URL 1.5초 안정) 뒤 logged-out-check.js: 로그아웃 표식 발견
                                              → Provider.GetLoginUrl()로 이동 후 다시 판단
 → [자동 입력] 로그인 페이지라면
   → 서비스의 기본 계정 조회 → LoginProvider에 맞는 LoginFormSpec 선택(없으면 휴리스틱)
   → (소셜 로그인이면 해당 버튼을 눌러 제공자 페이지로 이동)
   → Unprotect → autofill.js에 셀렉터와 값 전달
   → 입력란 채움 (input/change 이벤트를 발생시켜 React 등 프레임워크 상태 반영)
   → 2단계 로그인(Google 등, 이메일 먼저)이면 1단계 '다음'을 눌러 비밀번호 단계로 진행
     (비밀번호 제출이 아니므로 자동 제출 설정·LoginGuard와 무관하게 수행. 의도된 동작)
 → [자동 제출] LoginGuard.Evaluate(account)가 Allowed일 때만 (CanAutoSubmit은 보조 메서드)
   → 제출, LastAutoSubmitAt 기록
 → [결과 판정]
   ├ 로그인 페이지를 벗어남           → 성공: LastLoginAt 갱신, LoginFailCount = 0
   └ 일정 시간 안에 다시 로그인 화면  → 실패: LoginFailCount++
                                        → 2회 연속이면 자동 제출 끄고 WebView 상단에 안내 배너
```

**LoginGuard (반복 제출 방지)**
- 같은 계정은 `LastAutoSubmitAt` 이후 10분 안에 다시 자동 제출하지 않음(설정으로 조정 가능)
- `LoginFailCount >= 2`이면 자동 제출을 막음. 사용자가 계정 편집에서 비밀번호를 고치면 초기화

**구현 메모 (2026-10-13)**
- `LoginAssistService`(App)가 `ServiceHostManager.HostCreated`로 모든 호스트의 `LoginPageDetected`·`PageSettled`를 구독한다. 로그인 페이지 판정은 Provider의 URL 정규식이다.
- 로그아웃 상태 판정(FR-ACC-08)은 `PageSettled`(DOMContentLoaded 또는 SPA 라우팅 뒤 URL이 1.5초 그대로일 때) 시점에 `logged-out-check.js`로 한다. DB `LoginFormSpecJson.loggedOutMarker`가 있으면 그 요소가 보이는지로, 없으면 휴리스틱("보이는 로그인 링크·버튼이 있고 로그아웃 링크는 없음")으로 판단한다. 로그아웃 상태면 Provider의 로그인 URL로 보내되, 로그인이 확인될 때까지 서비스당 1회만 보낸다(반복 리디렉션 방지). 앱의 "로그아웃(쿠키 삭제)"는 저장된 계정이 있으면 바로 로그인 페이지로 간다.
- 서비스 자체 로그인이 상위 계정인 경우(치지직=네이버, YouTube=Google)는 Provider의 `PrimaryLoginProvider`로 선언하고, 그 방식의 계정은 자체 ID처럼 자동 입력한다. 서비스 화면에서 제공자 버튼을 눌러야 하는 소셜 로그인(TVING의 카카오 등)은 순차 지원이다.
- **쿠키 서명 학습(Wavve처럼 화면으로 로그인 상태를 알 수 없는 서비스)**: 로그인 페이지에 있을 때의 쿠키 이름을 기준선으로 두고, 자동 입력 뒤 서비스 도메인으로 로그인 관련 POST가 관찰된 다음 일반 페이지에서 "현재 쿠키 이름 − 기준선"(분석용 쿠키 제외)을 `AppSettings`의 `Login.CookieSignature.{code}`(키 상수는 `SettingKeys`, 값은 쿠키 이름 JSON 배열)에 저장한다. 이후 판정은 서명 쿠키의 과반 존재 여부로 한다(과반 이상=로그인). 쿠키 값은 읽지 않는다. 서명이 있는 서비스는 화면 검사보다 먼저 판정해 약 2초 안에 끝난다.
- 로그아웃 상태로 판정되면 서비스당 한 번 자동으로 로그인 페이지로 보내고, 그 뒤 로그인 없이 돌아오면 강제 이동 대신 "로그아웃 상태입니다 [로그인]" 배너를 띄운다.
- `autofill.js`는 셀렉터가 없어도 "보이는 비밀번호 입력란 + 그 앞의 텍스트 입력란 + 폼의 제출 버튼" 휴리스틱으로 동작한다. DB 셀렉터가 있으면 우선한다. SPA가 폼을 늦게 그리므로 8초 동안 0.7초 간격으로 재시도한다.
- 성공/실패 판정은 제출 뒤 최대 20초 동안 현재 URL이 로그인 페이지를 벗어나는지로 한다(인라인 오류는 URL이 안 바뀌므로 시간 초과 = 실패).
- 값 전달은 `ScriptLoader`가 JSON 직렬화해 `__ARGS__`에 넣는다. 복호화한 비밀번호는 스크립트 문자열을 만든 직후 참조를 버린다.

> 보안: 복호화한 비밀번호는 `ExecuteScriptAsync`에 넘기기 직전에만 메모리에 두고, 로그에 남기지 않습니다. 스크립트는 **해당 서비스 도메인에서만** 실행합니다(URL 호스트 검증).
