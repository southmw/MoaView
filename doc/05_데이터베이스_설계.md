# 05. 데이터베이스 설계

## 1. 개요

| 항목 | 내용 |
|------|------|
| DBMS | SQLite 3 (`Microsoft.EntityFrameworkCore.Sqlite`) |
| 파일 | `%LOCALAPPDATA%\MoaView\moaview.db` |
| 스키마 관리 | EF Core Code-First 마이그레이션 |
| 시간 저장 | UTC, ISO-8601 TEXT (EF Core 기본 변환) |
| 동시성 | 단일 사용자·단일 프로세스. 중복 실행은 Mutex로 막음 (Phase 4 예정) |

## 2. ERD

```
┌────────────────────┐ 1     N ┌────────────────────┐
│ StreamingServices  │─────────│ Accounts           │
├────────────────────┤         ├────────────────────┤
│ Id (PK)            │         │ Id (PK)            │
│ Code (UQ)          │         │ ServiceId (FK)     │
│ Name               │         │ DisplayName        │
│ HomeUrl            │         │ LoginId            │
│ ...                │         │ EncryptedPassword  │
└─────────┬──────────┘         │ ...                │
          │ 1                  └────────────────────┘
          │
          │ N                   ┌────────────────────┐
┌─────────┴──────────┐          │ AppSettings        │
│ Bookmarks          │          ├────────────────────┤
│ (Could, 미구현)    │          │ Key (PK)           │
├────────────────────┤          │ Value              │
│ Id (PK)            │          └────────────────────┘
│ ServiceId (FK)     │
│ Title, Url         │
└────────────────────┘
```

> Bookmarks는 Could 항목으로 아직 엔티티·마이그레이션이 없습니다. 현재 테이블은 StreamingServices, Accounts, AppSettings 3개입니다.

## 3. 테이블 정의

### 3.1 StreamingServices (사이트 정보)

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|------|------|:---:|--------|------|
| Id | INTEGER | N | AUTOINCREMENT | PK |
| Code | TEXT | N | | 고유 코드 (`netflix`, `tving`, `wavve`, `youtube`, `chzzk`, 사용자 정의는 `custom_{guid}`) UNIQUE |
| Name | TEXT | N | | 표시 이름 |
| HomeUrl | TEXT | N | | 시작 URL |
| LoginUrl | TEXT | Y | | 로그인 페이지 URL |
| LoginUrlPattern | TEXT | Y | | 로그인 페이지 판별 정규식 |
| AllowedHosts | TEXT | N | `[]` | 앱 안에서 탐색을 허용할 호스트 목록(JSON 배열, ValueConverter). 예: `["*.netflix.com"]`. 비어 있으면(`[]`) Provider 기본값을 씀 |
| IconPath | TEXT | Y | | 캐시한 파비콘의 절대 경로(`%LOCALAPPDATA%\MoaView\icons\{code}.png`). `FaviconCache`가 실행 중에 채우고, 파일이 없으면 사이드바는 이니셜 아이콘을 쓰며 다음 방문 때 다시 받음. 브랜드 로고는 앱에 넣지 않음(D-08) |
| AccentColor | TEXT | Y | | 브랜드 색상 (`#E50914`) |
| SortOrder | INTEGER | N | 0 (엔티티) | 사이드바 순서 |
| IsEnabled | INTEGER | N | 1 | 표시 여부 |
| IsBuiltIn | INTEGER | N | 0 (엔티티) | 기본 제공 여부(기본 서비스는 삭제 불가, 숨김만 가능) |
| ProviderCode | TEXT | N | `generic` | 사용할 Provider |
| UserAgentOverride | TEXT | Y | | 서비스별 User-Agent |
| LoginFormSpecJson | TEXT | Y | | 자동 입력 셀렉터(JSON). Provider 기본값보다 우선 |
| ZoomFactor | REAL | N | 1.0 | 확대 배율 |
| PauseOnSwitch | INTEGER | N | 1 | 다른 서비스로 전환할 때 일시정지 |
| LastUrl | TEXT | Y | | 마지막 방문 URL |
| CreatedAt | TEXT | N | | 생성 시각 |
| UpdatedAt | TEXT | N | | 수정 시각 |

> 기본값 열에서 "(엔티티)"로 표시한 값은 DB DEFAULT 제약이 아니라 C# 엔티티의 기본값(0/false)입니다. 나머지 기본값은 `AppDbContext`의 `HasDefaultValue`로 DB에도 둡니다.

**LoginFormSpecJson 예시** (로그인 방식별로 스펙을 둠)
```json
{
  "loggedOutMarker": "a[href*='/login']",
  "forms": {
    "native": {
      "idSelector": "input[name='userLoginId']",
      "passwordSelector": "input[name='password']",
      "submitSelector": "button[type='submit']"
    },
    "naver": {
      "entrySelector": "button.login-naver",
      "idSelector": "#id",
      "passwordSelector": "#pw",
      "submitSelector": "#log\\.login"
    }
  }
}
```
- `loggedOutMarker`: 일반 페이지에서 로그아웃 상태를 판단하는 표식(FR-ACC-08)
- `entrySelector`: 소셜 로그인일 때 서비스 화면에서 먼저 눌러야 하는 버튼
> 현재 상태: 기본 5종 Provider에는 LoginFormSpec을 두지 않고 `autofill.js`의 휴리스틱(보이는 비밀번호 입력란 + 그 앞의 ID 입력란 + 폼의 제출 버튼)으로 동작합니다. 휴리스틱이 맞지 않는 서비스만 이 컬럼에 셀렉터를 넣으며(앱에서 Ctrl+Shift+L로 뽑은 로그로 구조 확인), 값이 있으면 휴리스틱보다 우선합니다. 사이트가 바뀌면 이 값만 고치면 됩니다.

### 3.2 Accounts (로그인 정보)

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|------|------|:---:|--------|------|
| Id | INTEGER | N | AUTOINCREMENT | PK |
| ServiceId | INTEGER | N | | FK → StreamingServices.Id (ON DELETE CASCADE) |
| DisplayName | TEXT | N | | 표시 이름 (예: "내 계정", "가족 계정") |
| LoginId | TEXT | N | | 로그인 ID/이메일(평문, 표시용) |
| EncryptedPassword | BLOB | Y | | DPAPI로 암호화한 비밀번호. NULL이면 세션만 사용 |
| LoginProvider | TEXT | N | `native` | 로그인 방식: `native`(서비스 자체 ID) / `cjone` / `naver` / `kakao` / `google` / `tid` 등. 어떤 LoginFormSpec을 쓸지 결정 |
| ProfileName | TEXT | N | | WebView2 프로필 이름 UNIQUE. 첫 계정은 서비스 프로필 `svc_{code}`를 그대로 쓰고, 이후 계정은 `svc_{code}_{GUID N형식}`(최대 40자). 예: `svc_netflix`, `svc_netflix_3f2a...` |
| IsDefault | INTEGER | N | 0 (엔티티) | 서비스의 기본 계정 |
| AutoFillEnabled | INTEGER | N | 1 | 자동 입력 사용 |
| AutoSubmitEnabled | INTEGER | N | 0 | 자동 제출 사용 (기본 끔) |
| LastLoginAt | TEXT | Y | | 마지막 로그인 성공 시각 |
| LastAutoSubmitAt | TEXT | Y | | 마지막 자동 제출 시각 (반복 방지용) |
| LoginFailCount | INTEGER | N | 0 (엔티티) | 연속 자동 로그인 실패 횟수. 성공하거나 비밀번호를 고치면 0 |
| CreatedAt | TEXT | N | | |
| UpdatedAt | TEXT | N | | |

- 인덱스: `IX_Accounts_ServiceId`, `UX_Accounts_ProfileName`
- 제약: 서비스 하나에 `IsDefault = 1`인 계정은 최대 1개(Partial Unique Index `UX_Accounts_ServiceId_Default`: `ServiceId WHERE IsDefault = 1`)
- "(엔티티)" 기본값은 3.1절과 같이 C# 엔티티 기본값(0/false)이며 DB DEFAULT가 아닙니다.

### 3.3 AppSettings (앱 설정, Key-Value)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| Key | TEXT (PK) | 설정 키 |
| Value | TEXT | 값. `AppSettingsStore`가 JSON 직렬화(camelCase)하므로 문자열은 따옴표를 포함해 저장됨(예: `"last"`) |

| Key | 예시 값 | 설명 |
|-----|---------|------|
| `Startup.ServiceMode` | `"last"` / `"fixed"` | 시작 서비스 결정 방식 |
| `Startup.ServiceId` | `1` | 고정 시작 서비스 |
| `Startup.LastServiceId` | `3` | 마지막으로 보던 서비스(FR-SVC-07). 전환할 때마다 갱신 |
| `Window.Placement` | `{"x":100,"y":100,"width":1600,"height":900,"state":"Maximized"}` | 창 상태(`WindowPlacement` 레코드, DIP 단위) |
| `Window.MiniPlacement` | `{"x":1424,"y":736,"width":640,"height":370,"state":"Normal"}` | 미니 플레이어 창의 마지막 위치·크기(FR-PLY-07). 해제할 때 저장, 다음 진입 때 복원. `state`는 쓰지 않음 |
| `UI.Theme` | `"dark"` | 테마 `"dark"`(기본) / `"light"` / `"system"`(Windows 앱 모드 따름). `ThemeService`가 시작 때와 설정 > 일반에서 적용(FR-SET-02) |
| `UI.SidebarCollapsed` | `true` | 사이드바 접힘. 기본값 true(접힘) |
| `Player.SuspendAfterSeconds` | `300` | 비활성 WebView Suspend 대기 시간. DB 값 우선, 없으면 `appsettings.json`의 `Player` 절 |
| `Player.MaxAliveHosts` | `3` | 동시에 유지할 WebView 최대 개수. DB 값 우선, 없으면 `appsettings.json` |
| `Player.PauseOnSwitch` | `true` | 전환 시 일시정지(전역). `appsettings.json` 전용이며 DB에는 두지 않음. 서비스별 값은 `StreamingServices.PauseOnSwitch` |
| `Login.CookieSignature.{code}` | `["NetflixId","SecureNetflixId"]` | 서비스별 로그인 쿠키 서명(쿠키 이름 JSON 배열). `LoginAssistService`가 학습해 저장하며 쿠키 값은 저장하지 않음(04 아키텍처 5.3절) |
| `Data.ResetWebViewOnStart` | `true` | 설정 > 데이터 "모든 서비스 데이터 초기화"(FR-SET-04)를 예약. 다음 시작 때 `App`이 WebView2 폴더를 지우고 키를 삭제. 실행 중에는 브라우저 프로세스가 폴더를 잡고 있어 바로 지울 수 없음 |
| `Security.LockEnabled` | `false` | 실행 잠금 (Could) |

## 5. 자격증명 암호화 상세

### 5.1 방식

```csharp
public sealed class DpapiCredentialProtector : ICredentialProtector
{
    // 앱 고유 엔트로피 = SHA-256(소스 상수 "MyOTTPlayer.Credential.v1" + 설치 시 생성한 32바이트 난수)
    // 난수는 %LOCALAPPDATA%\MoaView\.entropy(숨김 파일)에 두며, DB 백업 시 함께 백업해야 한다 (구현: DpapiCredentialProtector)
    private readonly byte[] _entropy;

    public byte[] Protect(string plainText) =>
        ProtectedData.Protect(Encoding.UTF8.GetBytes(plainText), _entropy, DataProtectionScope.CurrentUser);

    public string Unprotect(byte[] cipher) =>
        Encoding.UTF8.GetString(ProtectedData.Unprotect(cipher, _entropy, DataProtectionScope.CurrentUser));
}
```

### 5.2 보안 수준과 한계

| 위협 | 방어 여부 | 설명 |
|------|:---:|------|
| DB 파일 유출(다른 PC로 복사) | 방어 | 다른 Windows 계정·PC에서는 복호화 불가 |
| 같은 Windows 계정에서 실행되는 악성코드 | 부분 방어 | 엔트로피로 난이도를 높이지만 완전한 방어는 아님(DPAPI의 본질적 한계) |
| 화면 노출 | 방어 | UI에서 비밀번호 마스킹, 보기 버튼은 Windows Hello 인증 후(Could) |
| 로그 노출 | 방어 | 비밀번호 필드는 로깅 대상에서 제외 |

### 5.3 백업/복원 시 주의

- DB를 백업해서 **같은 PC, 같은 Windows 계정**에 복원하면 비밀번호도 정상 복원됩니다.
- PC를 옮기거나 Windows를 다시 설치하면 `EncryptedPassword`를 복호화할 수 없으므로, 그때는 계정을 다시 입력하도록 안내합니다(서비스 정보와 설정은 그대로 이전됩니다).

## 6. EF Core 매핑 메모 (구현 완료, 2026-10-13)

- `DbContext`는 `IDbContextFactory<AppDbContext>`로 주입합니다(WPF의 긴 수명 ViewModel에서 컨텍스트 수명 문제 방지). 저장소는 호출마다 컨텍스트를 짧게 열고 닫습니다.
- `AllowedHosts`는 ValueConverter로 JSON 배열 문자열에 매핑합니다. `LoginFormSpecJson`은 문자열 그대로 두고 Provider가 파싱합니다.
- `CreatedAt`, `UpdatedAt`은 `ITimestamped` 엔티티에 대해 `SaveChangesAsync` 재정의에서 UTC로 자동 설정합니다.
- 연결 문자열: `Data Source=%LOCALAPPDATA%\MoaView\moaview.db` (`Cache=Shared`는 의도적으로 쓰지 않음. SQLite 문서가 공유 캐시를 권하지 않고, 짧은 연결을 여러 개 여는 구조에서는 이점이 없음)
- 마이그레이션은 `src/MoaView.Infrastructure/Persistence/Migrations/`에 있고, 앱 시작 시 `DatabaseInitializer`가 `MigrateAsync` 후 Seed를 실행합니다. 새 마이그레이션은 App을 시작 프로젝트로 지정해 만듭니다(라이브러리만으로는 Windows SDK 프로젝션 어셈블리를 못 찾음):
  `dotnet ef migrations add <Name> --project src/MoaView.Infrastructure --startup-project src/MoaView.App --output-dir Persistence/Migrations`
- 테스트는 SQLite in-memory 연결에 실제 마이그레이션을 적용해 스키마까지 검증합니다(`SqliteTestDatabase`).
- Seed는 `AllowedHosts`·`LoginUrlPattern`을 비워 두어 Provider 기본값이 쓰이게 합니다. 사용자가 설정에서 값을 넣으면 DB 값이 우선합니다.
