# 06. UI/UX 설계

## 1. 디자인 원칙

1. **콘텐츠 우선**: 셸 UI는 최소한으로 두고, 영상 영역을 최대로 씁니다.
2. **빠른 전환**: 서비스 전환은 클릭 한 번 또는 단축키 하나로 합니다.
3. **일관성**: 서비스가 달라도 전체화면, 뒤로가기, 새로고침은 같은 방식으로 동작합니다.
4. **다크 테마 기본**: 영상 시청 환경에 맞춰 어두운 테마를 기본으로 합니다. UI 라이브러리는 WPF-UI(Fluent 스타일)를 씁니다(D-13).

## 2. 메인 화면

│ N  │                                                             │
│    │                                                             │
│ T  │                                                             │
│    │                                                             │
│ W  │                WebView2 (서비스 웹 플레이어)                │
│    │                                                             │
│ ▶  │                                                             │
│    │                                                             │
│ 치 │                                                             │

상단 도구막대와 탐색 버튼은 두지 않습니다(Netflix 앱처럼). 셸 UI는 타이틀바와 사이드바뿐이고, 나머지 영역은 모두 WebView2가 씁니다. 뒤로·앞으로는 단축키와 마우스 측면 버튼으로만, 새로고침·홈은 단축키와 서비스 아이콘의 컨텍스트 메뉴로 제공합니다.

| 영역 | 구성 요소 | 설명 |
|------|-----------|------|
| 타이틀바 | "현재 페이지 제목 - MoaView", 창 버튼 | 커스텀 타이틀바(WPF-UI `TitleBar`). 페이지 제목이 없으면 "MoaView" |
| 사이드바 (상단) | 펼치기/접기 버튼(≡, Ctrl+B), 서비스 아이콘 목록 | 서비스 아이콘은 실행 중에 받아 캐시한 파비콘(FR-SVC-06, `FaviconCache`), 없으면 브랜드 색 원형 + 이니셜(D-08). 선택된 서비스는 왼쪽 강조 막대, 로드된 서비스는 점(●) 표시. 계정이 2개 이상인 서비스는 아이콘 모서리에 현재 계정 이니셜 배지(다중 계정 지원 시) |
| 사이드바 (하단) | 미니 플레이어(▭, Ctrl+M), 전체화면(⛶, F11), 서비스 추가(＋, `ServiceEditDialog`를 바로 열어 추가 후 선택), 설정(⚙, Ctrl+,, `SettingsWindow`) | 사이드바를 펼치면 아이콘 옆에 이름과 단축키 표시 |
| 서비스 컨텍스트 메뉴 | 계정 관리..., 서비스 편집..., 홈으로, 새로고침, 로그아웃 (쿠키 삭제) | 사이드바의 서비스 아이콘을 우클릭. 서비스 편집은 설정 > 서비스의 수정과 같은 대화상자. 계정 전환(계정이 2개 이상일 때 하위 메뉴, D-11 Could)은 예정 |
| 메인 | 서비스별 WebView2 | 서비스마다 인스턴스를 유지하고 Visibility로 전환 |

- **주소 표시 없음**: 사용자가 URL을 입력하거나 볼 일이 없으므로 주소 표시줄을 두지 않습니다. 허용 호스트 밖 탐색은 `NavigationStarting`에서 막지 않고 로그만 남기며(차단 예정 없음), `AllowedHosts`는 새 창 요청을 앱 안·OAuth 대화상자·기본 브라우저로 가를 때만 씁니다. 현재 URL은 재시작 복원용(`LastUrl`)으로만 내부에 보관합니다.
- **탐색 버튼 없음**: 뒤로/앞으로/새로고침/홈 전용 버튼을 두지 않습니다. 각 서비스의 웹 UI가 자체 탐색을 제공하므로, 셸은 단축키(4절)와 마우스 측면 버튼(뒤로/앞으로, Chromium 기본 동작), 컨텍스트 메뉴로만 보조합니다.
- **계정 관리 위치**: 서비스 아이콘의 컨텍스트 메뉴 "계정 관리..."로 `AccountsWindow`(별도 창)를 엽니다. 설정 > 계정 탭은 서비스별 요약과 "관리..." 버튼으로 같은 창을 엽니다. 계정 전환(D-11, Could)은 컨텍스트 메뉴에 두되 계정이 1개뿐인 서비스는 항목을 표시하지 않을 예정입니다.

### 2.2 전체화면 모드

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│                                                                  │
│                    영상 (모니터 전체, 셸 UI 숨김)                   │
│                                                                  │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

- 진입: 웹 플레이어의 전체화면 버튼 / F11 / 사이드바 ⛶ / 영상 더블클릭(웹 플레이어 기본 동작)
- 해제: Esc / F11 / 웹 플레이어의 전체화면 해제 버튼
- 작업 표시줄까지 덮고, 창이 있는 모니터 기준으로 표시합니다.
- Airspace 문제로 영상 위에 WPF 오버레이를 그리지 않습니다. 전체화면·미니 플레이어 중에는 배너를 표시하지 않고 로그만 남기며, 진입 시 열려 있던 배너도 닫습니다([03 기술 검토](03_기술_검토.md) 4.2절).

### 2.3 미니 플레이어 모드와 PIP (D-12)

```
                                          ┌──────────────────┐
                                          │                  │
                                          │  WebView2 (영상)  │ ← 항상 위, 테두리 없음
                                          │                  │
                                          └──────────────────┘
                                             ↑ 우하단 기본, 드래그 이동, 모서리 크기 조절
```

| 모드 | 동작 | 진입/해제 |
|------|------|-----------|
| 미니 플레이어 | 메인 창 자체를 작은 Topmost 창(480×280: 영상 270 + 상단 바 10px, 비율 고정 없음, 작업 영역 우하단)으로 바꾸고 타이틀바·사이드바를 숨김. 상단 바는 드래그로 이동. WebView2 인스턴스는 그대로라 재생이 끊기지 않음 | 진입: 사이드바 미니 플레이어 버튼 / Ctrl + M. 복귀: 상단 바 더블클릭 / Esc / Ctrl + M |
| PIP | 서비스 웹 플레이어의 PiP 기능(Chromium 내장 PiP 창)을 사용. 앱은 단축키로 현재 `<video>`에 `requestPictureInPicture()`/`exitPictureInPicture()`를 호출해 줌 | Ctrl + P 토글 / PiP 창의 닫기 버튼 |

- 별도 창으로 WebView2를 옮기지 않고 메인 창을 변형하는 이유: WPF의 WebView2는 창 사이를 옮기기 어렵고, 옮기면 재생이 끊깁니다. 창 하나를 모양만 바꾸는 편이 안정적입니다.
- 미니 플레이어에서는 창 위에 WPF 컨트롤을 겹칠 수 없으므로(Airspace), WebView 위가 아니라 위쪽에 10px 바를 두고 드래그 이동·더블클릭 복귀를 처리합니다. 크기 조절은 창 모서리 그립이며(최소 320×190), 해제할 때 위치·크기를 `Window.MiniPlacement`에 저장해 다음 진입 때 복원합니다. 저장된 위치가 화면 밖이면 작업 영역 오른쪽 아래 기본 위치를 씁니다.
- PiP 창은 Chromium이 만드는 별도 OS 창이라 앱이 모양을 제어하지 못합니다. WebView2에서 PiP가 열리는 것은 PoC P10에서 확인했습니다(단축키 입력이 사용자 제스처로 인정되어 `ExecuteScriptAsync`로 열림).

왼쪽 탭 목록과 오른쪽 패널로 구성한 모달 창입니다(사이드바 ⚙ 또는 Ctrl+,). 항목을 바꾸면 바로 저장하며 확인 버튼은 없습니다. 창을 닫으면 `MainViewModel.ReloadServicesAsync`가 사이드바를 다시 읽고, 수정·삭제·비활성화된 서비스의 WebView만 해제해 다음 선택 때 새 설정으로 다시 만듭니다(순서·활성화만 바뀐 서비스는 그대로 유지).

| 탭 | 항목 | 상태 |
|----|------|------|
| 일반 | 시작 서비스(마지막 / 고정 + 콤보), 테마(다크·라이트·Windows 설정 따름) | 구현. 중복 실행 방지는 항상 켜져 있어 안내 문구만 표시. "닫기(X)를 누르면 트레이로 보냄" 옵션(D-18, 기본 끔). 트레이 아이콘은 항상 표시되며 클릭으로 창 토글, 우클릭 메뉴는 열기·설정·종료 |
| 서비스 | 목록(순서·이름·주소·표시·전환 시 일시정지·배율·종류), 추가/수정/삭제, 위로/아래로 | 구현. 정렬은 행 드래그 앤 드롭(D-18)과 위/아래 버튼. 기본 제공 서비스는 삭제 불가, 숨김만 가능. 편집 대화상자는 3.3절 |
| 계정 | 서비스별 계정 요약(기본 계정 ID·자동 로그인 방식)과 "관리..." → `AccountsWindow` | 구현 |
| 재생 | Suspend 대기 시간(초), 동시 유지 개수 | 구현. 미니 창 위치·크기는 자동 저장(안내만 표시). 하드웨어 가속 표시는 예정 |
| 단축키 | 단축키 목록(읽기 전용) | 구현. 변경은 Could |
| 데이터 | 데이터 폴더·로그 폴더 열기, DB 백업(`VACUUM INTO`), 모든 서비스 데이터 초기화(쿠키·캐시), 모든 데이터 초기화(처음 상태로) | 구현. 두 초기화 모두 실행 중에는 못 지우므로 다음 시작 때 수행하며 "지금 다시 시작" 선택 가능(쿠키·캐시는 `Data.ResetWebViewOnStart`, 전체는 `reset-all.flag`, D-18). DB 복원 UI는 두지 않음(수동 파일 복사) |
| 정보 | 앱 버전, WebView2 런타임 버전, .NET 버전, 로그 폴더 | 구현. DRM 진단은 예정 |

### 3.2 로그인 상태 알림 (WebView 상단 배너)

| 상황 | 배너 문구(안) | 버튼 |
|------|---------------|------|
| 세션 만료, 자동 입력 완료 | "로그인이 끊겨서 저장된 계정으로 입력했습니다." | [계정 관리] [닫기] |
| 자동 로그인 실패 | "자동 로그인에 실패했습니다. 비밀번호를 확인해 주세요." | [계정 수정] [닫기] |
| 자동 제출 보류(쿨다운·연속 실패) | "자동 제출을 잠시 멈췄습니다." | [계정 수정] [닫기] |
| 로그아웃 상태 재감지 | "로그아웃 상태입니다." (저장된 계정으로 로그인할 수 있음) | [로그인] [닫기] |
| 저장된 계정 없음 | "이 서비스의 계정을 저장하면 다음부터 자동으로 입력합니다." | [계정 저장] [다시 보지 않기] |
| 로그아웃(쿠키 삭제) 완료 | "로그아웃했습니다." | [닫기] |

> 배너는 WebView 위에 겹치지 않고 타이틀바와 WebView 사이에 자리를 차지하는 방식입니다(Airspace 문제 회피). 평소에는 숨겨져 있어서 영역을 차지하지 않고, 알림이 있을 때만 나타납니다. 전체화면 중에는 표시하지 않습니다.

### 3.3 서비스 편집 대화상자 (`ServiceEditDialog`)

```
┌ 서비스 추가 ───────────────────────────┐
│ 이름        [ Disney+               ] │
│ 홈 URL      [ https://...           ] │
│ 강조 색     [ #3B82F6           ] ●   │  ← 사이드바 이니셜 아이콘 색
│ ▸ 고급 (로그인 감지·허용 호스트)        │  ← 로그인 URL, 로그인 URL 정규식, 허용 호스트(줄마다 하나)
│                     [취소]  [저장]     │
└───────────────────────────────────────┘
```

- 사용자 정의 서비스는 코드 `custom_{8자리}`, Provider `generic`으로 만들어집니다(`StreamingService.CreateCustom`). 고급 항목을 비워 두면 홈 URL의 호스트와 하위 도메인만 앱 안에서 열고 나머지는 기본 브라우저로 넘깁니다.
- 기본 제공 서비스도 같은 대화상자로 이름·홈 URL·강조 색·고급 항목을 고칠 수 있고, 비워 둔 고급 항목은 전용 Provider 기본값을 씁니다(NFR-08).
- 검증: 이름 필수, URL은 http(s) 절대 주소, 색은 `#RRGGBB`, 정규식은 컴파일 확인, 호스트는 `*.example.com` 또는 `www.example.com` 형식.

| Ctrl + Tab / Ctrl + Shift + Tab | 다음/이전 서비스 | 앱 |
| Alt + ← / Alt + → | 뒤로/앞으로 (마우스 측면 버튼도 동일) | 서비스 |
| F5 / Ctrl + R | 새로고침 | 서비스 |
| Alt + Home | 서비스 홈 | 서비스 |
| Ctrl + + / Ctrl + - / Ctrl + 0 | 확대/축소/초기화 | 서비스 |
| Ctrl + , | 설정 열기 | 앱 |
| Ctrl + B | 사이드바 접기/펼치기 | 앱 |
| Ctrl + M | 미니 플레이어 모드 토글 | 앱 |
| Ctrl + P | 현재 영상 PIP 토글 | 서비스 |
| Ctrl + Shift + L | 로그인 폼 분석 결과를 로그에 기록 (개발용) | 서비스 |

> 주의: WebView2에 포커스가 있으면 WPF가 키 입력을 받지 못합니다. 다만 WPF용 WebView2 컨트롤이 `AcceleratorKeyPressed`를 `PreviewKeyDown`으로 올려 주므로, `AcceleratorKeyPressed`를 직접 구독하지 않고 `MainWindow.PreviewKeyDown`에서 앱 단축키를 처리합니다. Space·화살표처럼 서비스 플레이어가 쓰는 키는 건드리지 않고 웹으로 그대로 넘깁니다. 탐색 버튼이 없으므로 뒤로/앞으로/새로고침/홈 단축키는 MVP 필수(FR-NAV-01)이며, 설정 > 단축키 탭에 목록을 보여 줍니다.
