## 2. 점검했으나 문제 없음

- **자격증명 암호화**: `DpapiCredentialProtector`는 `DataProtectionScope.CurrentUser`, 엔트로피 = SHA-256(앱 상수 + 설치 난수). 평문 바이트는 암호화 직후 `CryptographicOperations.ZeroMemory`로 지움. 변조·다른 난수·다른 사용자 복호화는 `CryptographicException`(테스트 3개).
- **로그에 비밀번호 없음**: 계정·자동 입력이 구현됐으나 `Account.EncryptedPassword`와 복호화 결과를 로그 매개변수로 넘기는 코드가 없음. `LoginAssistService`는 복호화한 비밀번호를 `autofill.js` 인자(JSON 직렬화)로만 넘기고 결과 문자열(`filled`, `id-only` 등)만 로그에 남긴다. 개발용 폼 분석(Ctrl+Shift+L)은 구조만 기록하고 값은 포함하지 않는다.
- **로컬 저장만**: 네트워크 호출은 서비스 페이지 로드뿐. 스토어 CRX 다운로드는 `Infrastructure/WebView/ExtensionInstaller.cs`로 옮겨 두었고 아직 호출하지 않는다. 텔레메트리·원격 로그 없음(NFR-06).
- **주입 스크립트**: 상수 스크립트 3개(일시정지, 전체화면 해제, PiP)와 포함 리소스 JS 7개(`autofill.js`, `form-analyze.js`, `logged-out-check.js`, `hover-probe.js`, `login-submitted-check.js`, `drm-probe.js`·`video-info.js`는 미사용). 인자는 `ScriptLoader`가 JSON 직렬화해 넣으므로 문자열 조립이 없고, 자동 입력은 서비스 허용 호스트 또는 Provider가 로그인 페이지로 판정한 URL에서만 실행한다(04 아키텍처 5.3절).
- **쿠키 서명 학습**: 로그인 전후 쿠키를 비교해 늘어난 쿠키의 **이름만** `AppSettings`(`Login.CookieSignature.{code}`)에 저장한다. 쿠키 값·도메인·만료는 읽지만 저장하지 않고(`GetCookieNamesAsync`가 이름만 반환), 분석용 쿠키(`_ga` 등)는 제외한다. 이름만으로는 세션을 복원할 수 없으므로 문제 없음.
- **로그인 POST 관찰**: `WebResourceResponseReceived`에서 서비스·로그인 제공자 호스트로 나가는 로그인 경로 POST의 발생 시각만 기록한다. 요청 URL·본문·헤더는 읽지 않고 로그에는 호스트만 남긴다.
- **sessionStorage 제출 표식**: `autofill.js`가 제출 시각을 같은 출처의 `sessionStorage`(`moaview.loginSubmitted`)에 남기고 `login-submitted-check.js`가 읽은 뒤 지운다. 값은 타임스탬프뿐이며 자격증명이 아니고, 탭 수명과 함께 사라진다.
- **hover 이벤트 주입**: `hover-probe.js`는 헤더 영역의 메뉴 트리거에 마우스 진입·이탈 이벤트만 보내고 클릭·입력은 하지 않는다. 페이지 상태를 바꾸지 않으며 서비스 허용 호스트에서만 실행한다.
- **설정 복원 입력 검증**: 창 위치는 가상 화면 안에 있을 때만 적용, 크기는 최소값 이상일 때만 적용. DB JSON 파싱 실패는 기본값으로 대체.
- **파일 경로**: 모든 데이터는 `%LOCALAPPDATA%\MoaView\` 아래. 실행 파일 폴더에 쓰지 않음. 사용자 입력으로 경로를 만들지 않음.
- **WebView2 프로필 격리**: 서비스마다 `svc_{code}` 프로필. 비공개 모드는 쓰지 않음(세션 유지가 목적).
- **외부 드롭**: `AllowExternalDrop=false`.
- **OAuth 팝업**: Provider가 OAuth 호스트로 판정한 요청에만 열리고, 같은 프로필을 공유해 쿠키가 전달됨. 팝업 창의 `WindowCloseRequested`로 닫힘. WebView2 보안 설정은 S-13으로 본 창과 동일하게 맞춤.

## 3. Phase 2 자동 입력 구현 시 지켜야 할 규칙

1. 복호화한 비밀번호는 `ExecuteScriptAsync` 호출 직전에만 만들고, 호출 후 변수 참조를 버린다. 로그·예외 메시지·배너에 절대 넣지 않는다.
2. 자동 입력 스크립트는 현재 URL이 서비스 허용 호스트이거나 Provider가 로그인 페이지로 판정한 URL일 때만 실행한다. 소셜 로그인 제공자 페이지(nid.naver.com 등)는 해당 `LoginProvider`일 때만 허용한다.
3. 셀렉터·값은 `JsonSerializer.Serialize`로 넣어 스크립트 주입을 막는다. 셀렉터는 DB 값(사용자 편집 가능)이므로 역시 직렬화한다.
4. 자동 제출은 계정별 옵트인(기본 끔)이며 LoginGuard(10분 쿨다운, 연속 2회 실패 중단)를 우회하는 경로를 두지 않는다(FR-ACC-10). 2단계 로그인(이메일 먼저)의 1단계 '다음' 클릭은 비밀번호 제출이 아니므로 자동 제출 설정·LoginGuard와 무관하게 수행한다(의도된 동작).
5. 웹 메시지(`IsWebMessageEnabled`)는 켜지 않는다. 스크립트 결과는 `ExecuteScriptAsync` 반환값으로 받고 데이터로만 취급한다(명령 실행 금지).
6. 계정 편집 화면의 비밀번호는 마스킹하고, "보기"는 Could(Windows Hello) 전까지 제공하지 않는다.
